# VK COVER MASTER

## 0. Purpose

This is the **single working source of truth** for the VK cover production system.

The goal is NOT to copy another designer's visual style.
The goal is to combine the user's own reference-derived visual language with useful engineering, automation, Figma, banner-generation and design-system ideas.

The final objective is:

> **Make the next VK cover from the same design language as the user's existing portfolio.**

---

# 1. MASTER VISUAL AUTHORITY

The user's own reference-derived visual system remains the authority for visual decisions.

GitHub projects are supporting infrastructure, not the source of creative style.

A new cover must look like it could naturally sit next to the supplied works.

It must NOT look like:
- a generic AI advertising banner;
- a standard Canva template;
- a random Behance-inspired design;
- a universal modern-marketing layout;
- a cover filled with invented blocks, icons, cards and benefits.

The niche changes.
The visual construction language remains.

---

# 2. FORMAT

Target VK desktop canvas:

**1920 × 768 px**

Aspect ratio:

**2.5 : 1**

The cover is one continuous composition, not a collection of independent UI cards.

---

# 3. GLOBAL COMPOSITION

The portfolio is built around three visual layers:

### Layer A — Environment / background

The atmospheric world of the cover.

Possible environments include:
- interiors;
- dark textured spaces;
- smoke;
- architecture;
- landscapes;
- roads and vehicles;
- gaming environments;
- beauty interiors;
- food/product environments;
- abstract textures;
- paper/editorial textures;
- light studio environments.

Background is rarely a flat color. It can contain texture, photographic depth, gradients, environmental objects, soft light, shadows, particles, patterns and atmospheric haze.

### Layer B — Main subject

Usually one dominant visual subject:
- person;
- product;
- vehicle;
- building;
- device;
- food;
- equipment;
- group of people.

The subject should be large enough to become the second thing noticed after the headline.

### Layer C — Typography / information

Typography is integrated into the image rather than behaving like a website text panel.

Text can:
- overlap the subject;
- sit beside the subject;
- sit behind the subject;
- occupy a large empty area;
- extend across the central composition;
- integrate with the background.

---

# 4. TEXT + IMAGE = ONE COMPOSITION

Do NOT automatically create:

> background + person on right + text block on left + three cards

unless the reference family actually requires that structure.

Typography should interact with imagery:
- large type crossing behind a person;
- subject placed between words;
- title centered around a face;
- title occupying one side while subject occupies the other;
- title spanning almost the entire width;
- very large typography acting as an image-like object;
- typography touching or approaching the subject;
- asymmetric text placement.

The text is part of the image.

---

# 5. PRIMARY HEADLINE

The main headline is the strongest textual element.

Typical behavior:
- one main headline;
- sometimes two lines;
- occasionally three short lines;
- large scale;
- strong contrast;
- often condensed/display typography;
- sometimes elegant high-contrast serif;
- sometimes handwritten/script;
- sometimes wide geometric sans;
- sometimes distressed/custom-looking lettering.

There is **no single portfolio font**.

Observed families include:
- condensed display;
- bold grotesk;
- elegant serif;
- editorial serif;
- handwritten/script;
- brush lettering;
- geometric sans;
- custom/distressed display lettering.

Do not force one font on every cover. Match the typographic character to the closest reference family.

---

# 6. HEADLINE SCALE

The headline often occupies approximately:

**25–55% of the visual width**, depending on composition.

It is intentionally oversized.

The main title is allowed to become an image-like element.

The important property is visual weight, not wording.

---

# 7. TEXT HIERARCHY

Use a compact hierarchy.

### Level 1 — Main name / headline
Dominant.

### Level 2 — Descriptor
Examples:
- tattoo artist;
- tattoo studio;
- professional artist;
- service category;
- short positioning statement.

Usually significantly smaller than the headline.

### Level 3 — Supporting facts
Only when useful:
- city;
- years of experience;
- number of works;
- specialization;
- short benefit;
- contact;
- price;
- short service description.

### Level 4 — Microtext
Very small utility information, always subordinate.

### Rule
Do not invent 6–10 information blocks because space exists.
The references communicate the offer with a compact hierarchy.

---

# 8. TEXT POSITIONING PATTERNS

Use these as composition families, not mandatory templates.

### A. LEFT TEXT / RIGHT SUBJECT
Text occupies left third or left-center. Subject occupies right side.

### B. RIGHT TEXT / LEFT SUBJECT
Reverse version.

### C. CENTRAL TITLE + SUBJECT OVERLAP
Large title spans middle and person/product overlaps typography.

### D. FULL-WIDTH TYPOGRAPHIC TITLE
Large title stretches across the composition and the subject interrupts it.

### E. SPLIT COMPOSITION
Two visual zones with a strong vertical division.

### F. EDITORIAL ASYMMETRY
Large empty area on one side; subject placed away from center; typography balances the empty area.

For every new cover choose the family that best matches the supplied references for the niche.

---

# 9. SUBJECT POSITION

The main person/object is rarely tiny or passport-like.

Common scale:

**large / medium-large**

The subject usually occupies roughly:

**30–55% of canvas height**

and can occupy more when it is the central hero.

The subject may:
- extend above/below the optical text zone;
- be cropped by the canvas;
- overlap typography;
- overlap decorative objects;
- sit in foreground;
- be partially hidden by atmosphere.

### People

People are usually:
- cutout or semi-cutout;
- strongly integrated into background;
- professionally lit;
- separated by controlled edges;
- color-treated cinematically.

Avoid:
- generic stock-photo appearance;
- tiny headshots;
- perfectly centered passport-like portraits.

---

# 10. MULTIPLE PEOPLE

When several people are present, treat them as one group composition rather than profile cards.

Common structures:
- one dominant central person + secondary people;
- two people facing inward;
- several people forming a horizontal group;
- people distributed around a central title.

The group must read as one image.

---

# 11. PRODUCT / OBJECT COVERS

For products, the product becomes the hero.

Treatment:
- large scale;
- strong lighting;
- realistic material;
- integrated shadows;
- atmospheric background;
- sometimes multiple product instances.

Avoid:
- tiny isolated product floating in empty space;
- generic e-commerce product-card treatment.

---

# 12. BACKGROUND LANGUAGE

The portfolio uses varied backgrounds.

### Dark references
Common families:
- black;
- charcoal;
- deep brown;
- dark green;
- dark blue;
- burgundy;
- deep purple.

Often with:
- glow;
- haze;
- texture;
- smoke;
- gradients;
- photographic detail;
- subtle patterns.

### Light references
Common families:
- white;
- warm white;
- cream;
- pale blue;
- pale pink;
- light beige.

Often with:
- soft photography;
- low-contrast texture;
- delicate gradients;
- translucent shapes;
- soft shadows.

The portfolio does NOT have one mandatory palette.
Color follows brand, niche and concept.

---

# 13. ACCENT COLORS

Accent color is used selectively.

Observed behavior:
- red on dark compositions;
- cyan/teal on dark tattoo compositions;
- purple/magenta for beauty or creative projects;
- green for gaming/Xbox;
- yellow for automotive/construction/business;
- blue for technology/medical/automotive;
- gold/bronze for premium/editorial compositions.

Accent can appear in:
- one word of the headline;
- a button;
- a label;
- a line;
- a badge;
- a small icon;
- a secondary object.

Avoid turning every element into an accent.

---

# 14. CTA / BUTTONS

CTA elements, when needed, are compact.

Typical forms:
- pill;
- rounded rectangle;
- small highlighted label;
- dark translucent tag;
- colored button;
- text inside a compact badge.

They are NOT giant website buttons.

CTA should normally be a supporting element, not the main visual.

---

# 15. BADGES / LABELS / FACTS

Small information chips may carry:
- location;
- years of experience;
- number of works;
- specialization;
- price;
- service;
- short promise.

Typical placement:
- close to relevant subject;
- in empty space;
- near a corner;
- around the main composition.

They remain small and subordinate.

---

# 16. ICONS

Icons are used selectively.

When present they are:
- simple;
- small;
- supporting information;
- usually inside a badge or compact information element.

The portfolio does NOT rely on large icon grids as a primary design language.

Do not automatically add:
- 3 benefit icons;
- 6 service icons;
- feature grids.

Only use them when the reference family supports them.

---

# 17. DECORATIVE ELEMENTS

Common decorative language:
- texture;
- grain;
- smoke;
- light streaks;
- glow;
- particles;
- scratches;
- paper;
- brush marks;
- geometric lines;
- environmental objects;
- thematic patterns;
- frames;
- subtle borders.

Decoration supports the theme.
It must not become a collection of random AI decorations.

---

# 18. DEPTH

Typical depth stack:

1. distant background;
2. atmospheric texture;
3. secondary objects;
4. main subject;
5. typography;
6. foreground elements / glow / particles.

Objects can overlap.
Blur can separate depth planes.
Foreground objects may be partially cropped.

---

# 19. LIGHTING

Lighting is cinematic rather than flat.

Common behaviors:
- rim light around people;
- colored edge light;
- central glow;
- backlight;
- volumetric haze;
- product highlights;
- dark vignette;
- soft bloom.

Lighting should connect the subject to the background.
Do not simply paste a cutout on a background.

---

# 20. PHOTO TREATMENT

Typical treatment:
- background removal;
- color grading;
- contrast adjustment;
- glow;
- haze;
- shadow;
- edge light;
- atmospheric blending;
- partial transparency in background imagery.

The person/object should appear to belong to the environment.

---

# 21. NEGATIVE SPACE

Negative space is actively used for typography.

Do not fill every empty area.

Empty space can exist so that:
- headline remains readable;
- subject becomes dominant;
- composition breathes;
- a secondary fact can sit there.

---

# 22. INFORMATION DENSITY

The portfolio has **medium to high visual information density**, but information is organized around one dominant message.

Priority:

**MAIN MESSAGE → SUBJECT → SECONDARY MESSAGE → SMALL FACTS**

Not:

**10 equal pieces of information.**

The viewer should understand the cover in approximately one glance.

---

# 23. FORBIDDEN / DO NOT ADD AUTOMATICALLY

Do NOT automatically add:
- generic 3-card benefits;
- generic "Почему мы";
- FAQ;
- huge website-style CTA;
- floating glassmorphism cards;
- random 3D icons;
- random arrows;
- random circles;
- generic abstract blobs;
- unnecessary UI panels;
- excessive gradients;
- dozens of tiny labels;
- fake statistics;
- meaningless decorative text;
- stock business illustrations;
- generic corporate iconography;
- symmetrical template layouts when the reference is asymmetric;
- overly clean Canva-like blocks;
- excessive rounded cards inside the banner;
- random "premium" gold details;
- fake logos;
- fake brands;
- invented services.

---

# 24. PORTFOLIO CONTINUITY

Despite large differences in niche, the covers repeatedly share:

1. Strong hero — one visual idea dominates.
2. Large typography — title is visually important.
3. Integrated imagery — text and image are composed together.
4. Cinematic depth — background, subject and foreground use different planes.
5. Compact supporting information — secondary facts do not compete with the main message.
6. Theme-specific art direction — tattoo ≠ beauty ≠ automotive ≠ gaming.
7. High contrast — main message is readable at a glance.
8. Custom feel — avoid stock-template appearance.

---

# 25. COMPACT COMPOSITION DNA

Use this compact rule set for a new cover:

> ONE HERO IDEA
> ONE DOMINANT HEADLINE
> ONE DOMINANT SUBJECT
> 1–3 SUPPORTING INFORMATION GROUPS
> CINEMATIC ENVIRONMENT
> CONTROLLED DEPTH
> STRONG TYPOGRAPHIC SCALE
> ASYMMETRY WHEN APPROPRIATE
> THEME-SPECIFIC ART DIRECTION
> NO GENERIC TEMPLATE ELEMENTS

# 26. GITHUB RESEARCH — SUPPORTING TOOLKIT

The following GitHub projects are production references. They do not define visual style.

## A. Sai1099/Banner_Generation_Tool
https://github.com/Sai1099/Banner_Generation_Tool

**Priority: HIGH**

Why it matters:
- directly targets AI banner generation;
- supports custom banner prompts;
- supports multiple generated variations;
- has a text-overlay stage;
- uses historical banner data and tags as inputs;
- separates banner creation from content generation.

Useful ideas:
1. separate visual generation from text generation;
2. generate several composition candidates;
3. keep banner prompt and text overlay as separate stages;
4. use reference data instead of asking AI for an arbitrary “beautiful banner”.

Do NOT blindly copy its implementation or assume its current models are optimal. Use the workflow idea.

## B. thelzf/socialcover-photoshop-plugin
https://github.com/thelzf/socialcover-photoshop-plugin

**Priority: HIGH**

Why it matters:
- specifically targets social-media covers and banners;
- provides reusable templates;
- focuses on fast, consistent, brand-ready social graphics.

Useful ideas:
- treat social covers as a reusable production format;
- separate reusable templates/layout logic from final visual content;
- keep dimensions and brand consistency as part of the system.

## C. AmroJSawan/figma-design-system-skill
https://github.com/AmroJSawan/figma-design-system-skill

**Priority: VERY HIGH**

Useful ideas:
- inspect current Figma state before writing;

- avoid duplicate nodes;
- validate the result visually after changes;
- separate design-system rules from individual compositions;
- make the workflow idempotent so repeated commands do not create duplicates.

## D. thomas-lowry/figma-plugin-ds
https://github.com/thomas-lowry/figma-plugin-ds

**Priority: MEDIUM**

Useful as a reference for reusable Figma plugin UI components and styles.
It is a plugin architecture reference, not a source for cover visual style.

## E. figma-plugin-sdk/design-system
https://github.com/figma-plugin-sdk/design-system

**Priority: MEDIUM**

# 29. CORE PRODUCTION RULES

## Rule 1 — Reference first
Before generating a new cover, read this MASTER file.

## Rule 2 — Do not invent information
Only use the text supplied in the brief unless the user explicitly asks for copywriting.

Do not automatically add:
- benefits;
- icons;
- statistics;
- CTA;
- service lists;
- badges;
- decorative labels.

## Rule 3 — Separate typography and imagery
Typography can be generated/constructed as an independent asset.
Background/hero imagery can be generated separately.
The final composition is assembled in Figma when Figma is used.

## Rule 4 — Figma is the assembly layer
Use Figma for:
- editable typography;
- precise coordinates;
- scaling;
- spacing;
- layer order;
- final image placement;
- export.

## Rule 5 — Visual validation
After assembly, inspect the complete cover at 100% and at reduced size.
The cover must remain readable and visually coherent from a distance.

# 31. NEW COVER GENERATION ALGORITHM

For every new client brief:

## Step 1 — Identify the niche
Example: `Ремонт квартир в Краснодаре`

## Step 2 — Identify closest reference families
Do not copy one cover.
Find 2–4 references with similar:
- information density;
- subject type;
- business/personal positioning;
- visual mood;
- text hierarchy.

## Step 3 — Extract the composition
Write down:
- canvas;
- main headline zone;
- subject zone;
- secondary information zone;
- CTA zone;
- decorative zones;
- negative space;
- visual center.

## Step 4 — Replace the content
Only change:
- company/person;
- niche;
- city;
- services;
- relevant visual subject;
- color direction when necessary.

## Step 5 — Rebuild the visual world
Create:
- correct environment;
- correct objects;
- correct lighting;
- correct texture;
- correct atmosphere.

## Step 6 — Rebuild typography
Use the closest typographic character from the references.
Do not blindly reuse a font if it does not fit.

## Step 7 — Remove unnecessary elements
Ask:

> **Was this element actually supported by the reference portfolio?**

If no → remove it.

# 32. FINAL QUALITY CHECK

### Composition
- [ ] One clear visual focal point.
- [ ] Headline has dominant visual weight.
- [ ] Subject and typography interact.
- [ ] Intentional negative space exists.
- [ ] Not a generic left-text/right-person template.

### Typography
- [ ] Main headline is immediately readable.
- [ ] Text hierarchy is clear.
- [ ] No unnecessary text blocks.
- [ ] Typography matches the closest reference family.

### Imagery
- [ ] Main subject is large enough.
- [ ] Subject is integrated into environment.
- [ ] Lighting matches the scene.
- [ ] No stock-photo pasted-on appearance.

### Information
- [ ] Only useful supporting information remains.
- [ ] CTA is compact if present.
- [ ] Badges are subordinate if present.
- [ ] No invented marketing blocks.

### Portfolio continuity
- [ ] Could sit naturally next to the supplied references.
- [ ] Looks like a new work from the same designer.
- [ ] Does NOT look like a generic AI banner.
- [ ] Does NOT look like a copy of one specific reference.

There is no single GitHub repository that already contains the exact:

> AI → VK cover → Figma → same designer style

system we need.

The strongest approach is to combine:
- our own reference-derived visual system;
- banner-generation workflow ideas;
- social-cover automation ideas;
- Figma design-system automation;
- precise Figma assembly;
- visual QC.

This file is now the **only master working file** for future VK cover production.

The goal is not:

> “Make a beautiful banner.”

The goal is:

> **“Make the next banner from the same design language.”**
