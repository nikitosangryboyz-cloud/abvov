# VK COVER MASTER

## ОСНОВНОЕ ПРАВИЛО

Этот файл — единственный источник общих правил для создания обложек ВКонтакте.

Главная задача: создавать профессиональные, разнообразные обложки, которые ощущаются как продолжение одного сильного портфолио, но не превращаются в повторяющиеся AI-шаблоны.

**Главный принцип: сначала архитектура обложки, потом стилистика и детали.**

Обложка должна строиться не по формуле «красивый фон + огромный текст + объект», а как законченная коммерческая композиция:

**главный герой + чистая типографическая иерархия + аккуратные информационные элементы + тематический фон + контролируемая глубина.**

---

## WORKFLOW — ОБЯЗАТЕЛЬНЫЙ ПОРЯДОК

### СЦЕНАРИЙ A — ЕСТЬ ПРИКРЕПЛЁННОЕ ФОТО / РЕФЕРЕНС

1. Сначала прочитать `VK_COVER_MASTER.md` целиком.
2. Использовать файл как источник общих правил: формат, safe zone, архитектура, типографика, плашки, разнообразие и контроль качества.
3. Затем внимательно проанализировать прикреплённое изображение.
4. Извлечь из референса:
   - цветовую палитру;
   - характер шрифтов;
   - размер и вес заголовка;
   - наличие/отсутствие надзаголовка;
   - количество уровней текста;
   - количество и характер плашек;
   - масштаб главного объекта;
   - количество визуальных объектов;
   - композиционный ритм;
   - соотношение текста и изображения;
   - плотность и негативное пространство;
   - контраст;
   - свет;
   - глубину;
   - общую аккуратность композиции.
5. Отдельно определить **архитектуру информации**: что главное, что вторичное, сколько текстовых уровней и сколько информационных элементов.
6. Выбрать подходящую архитектурную схему из библиотеки или собрать новую комбинацию параметров.
7. Проверить Anti-Repetition Engine.
8. Проверить safe zone.
9. Только после этого создавать изображение.

Референс не копируется буквально. Из него извлекается визуальная система конкретной работы.

### СЦЕНАРИЙ B — НЕТ ПРИКРЕПЛЁННОГО ФОТО / РЕФЕРЕНСА

1. Сначала прочитать `VK_COVER_MASTER.md` целиком.
2. Использовать только правила файла и данные пользователя.
3. Не искать и не подменять внешний референс.
4. Выбрать архитектуру из библиотеки с учётом ниши и Anti-Repetition Engine.
5. Определить главного героя, типографическую иерархию, количество плашек и плотность.
6. Собрать изображение, цветовую систему и детали.
7. Проверить safe zone и разнообразие.
8. Создать новую обложку.

---

## FORMAT & SAFE ZONE

- Desktop VK cover: **1920×768 px**.
- Работать сразу в финальном размере.
- 2× размер не использовать.
- Safe zone — **не обрезка**.
- Важные элементы размещать только в **Y=130–718 px**.
- Верхние 130 px — зона без важного контента.
- Нижние 50 px — зона без важного контента.
- Фон может занимать весь canvas.

---

## АРХИТЕКТУРА ОБЛОЖКИ

Обложка не обязана содержать все элементы ниже. Их комбинация определяется выбранной схемой.

### 1. ГЛАВНЫЙ ГЕРОЙ

Главным героем может быть:

- один товар;
- человек;
- автомобиль;
- интерьер;
- оборудование;
- пара товаров;
- несколько связанных объектов;
- другой объект, непосредственно связанный с нишей.

Главный герой **не обязан быть огромным** и **не обязан находиться справа**.

### 2. ГЛАВНЫЙ ЗАГОЛОВОК

Заголовок должен быть чистым, выразительным и читаемым.

**Oversized-типографика не является обязательной.**

Размер выбирается по архитектуре. В сильной композиции заголовок может быть умеренно крупным и при этом доминировать за счёт шрифта, контраста, расположения и иерархии.

### 3. НАДЗАГОЛОВОК

Необязательный элемент.

Может использоваться как:

- бренд;
- категория;
- название студии/компании;
- короткий контекст;
- небольшой вводный уровень.

Не добавлять автоматически.

### 4. ПОДЗАГОЛОВОК / ПОДПИСЬ

Необязательный элемент.

Использовать только если он предоставлен пользователем или логически необходим в выбранной архитектуре и основан на данных задачи.

### 5. ИНФОРМАЦИОННЫЕ ПЛАШКИ

**Плашки являются полноценной частью композиционной схемы.**

Возможные варианты:

- 0 плашек;
- 1 плашка;
- 2 плашки;
- 3 плашки;
- больше — только при явной необходимости и соответствии референсу.

Плашки могут содержать только предоставленную пользователем информацию:

- город;
- доставка;
- преимущество;
- опыт;
- количество работ;
- характеристику товара;
- категорию;
- другую конкретную информацию из задачи.

Плашки должны быть:

- компактными;
- аккуратными;
- вторичными относительно героя и заголовка;
- визуально связанными;
- частью композиции, а не интерфейсом сайта.

**Не добавлять плашки ради украшения и не придумывать их содержание.**

### 6. ВТОРИЧНЫЕ ОБЪЕКТЫ

Допускаются только если они усиливают нишу и композицию.

---

## CONTENT RULES

Использовать только информацию пользователя.

Разрешено структурировать предоставленный текст между надзаголовком, заголовком, подписью и плашками.

Не придумывать:

- преимущества;
- услуги;
- цены;
- статистику;
- CTA;
- адреса;
- гарантии;
- отзывы;
- рекламные обещания;
- дополнительные факты.

Не добавлять случайные иконки, карточки, badges или декоративный текст.

---

## TYPOGRAPHY

Типографика должна быть **чистой и профессиональной**.

Предпочтение:

- modern grotesk;
- clean sans-serif;
- condensed display;
- editorial serif;
- аккуратный display-шрифт;
- другой выразительный шрифт, если он соответствует референсу.

Главное — **иерархия, а не максимальный размер**.

Если есть референс, сначала анализировать его шрифтовой характер.

### ЗАПРЕЩЕНО БЕЗ ПРЯМОЙ КОМАНДЫ ПОЛЬЗОВАТЕЛЯ

- tattoo-style;
- blackletter / готические;
- агрессивные tattoo brush;
- псевдо-гранжевые;
- чрезмерно декоративные шрифты;
- характерная tattoo-типографика.

---

## IMAGE DIRECTION

- Главный объект соответствует нише.
- Масштаб объекта осознанный.
- Объект профессионально интегрирован.
- Перспектива, свет, тени и глубина согласованы.
- Не использовать случайную stock-like композицию.
- Главный объект не обязан быть человеком.
- Главный объект не обязан находиться справа.
- Объект может быть перед текстом, за текстом, пересекать текст или находиться отдельно.

# COMPOSITION ARCHITECTURE

Схема — это **архитектура всей обложки**, а не только положение объекта.

Каждая схема описывается параметрами:

1. **Главный герой** — что является визуальным центром.
2. **Типографическая иерархия** — только заголовок / надзаголовок + заголовок / заголовок + подпись / несколько уровней.
3. **Плашки** — количество, расположение и функция.
4. **Роль героя** — доминирует / равен типографике / поддерживает типографику.
5. **Взаимодействие** — отдельно / перед текстом / за текстом / пересекает / встроен.
6. **Геометрия** — центральная / боковая / диагональная / асимметричная / editorial / свободная.

**Схема не является шаблоном.** Параметры должны комбинироваться.

---

# COMPOSITION LIBRARY — 30 АРХИТЕКТУРНЫХ СХЕМ

1. **HERO + TITLE + SINGLE PILL** — главный объект + чистый заголовок + одна компактная плашка.
2. **HERO + TITLE + TWO PILLS** — главный объект + заголовок + две небольшие информационные плашки.
3. **OVERLINE + TITLE + HERO** — небольшой надзаголовок + чистый заголовок + главный объект.
4. **OVERLINE + TITLE + HERO + PILL** — надзаголовок + заголовок + герой + одна плашка.
5. **TITLE + HERO + TWO INFO PILLS** — заголовок + герой + две информационные плашки.
6. **TITLE + HERO + THREE MICRO INFO** — заголовок + герой + три очень компактных информационных элемента.
7. **HERO DOMINANT + TYPE SUPPORT** — объект главный, типографика поддерживающая, минимум вторичной информации.
8. **TYPE DOMINANT + HERO SUPPORT** — типографика главная, объект акцентный.
9. **CENTER HERO + SIDE INFO** — герой ближе к центру, вторичная информация по сторонам.
10. **LEFT HERO + CENTER TYPE + RIGHT PILL** — герой слева, заголовок ближе к центру, одна плашка справа.
11. **RIGHT HERO + CENTER TYPE + LEFT PILL** — противоположная архитектура; не использовать подряд с №10.
12. **TITLE ABOVE HERO + INFO BELOW** — заголовок над объектом, компактная информация ниже.
13. **TITLE BESIDE HERO + INFO UNDER TITLE** — заголовок рядом с героем, вторичная информация под ним.
14. **TITLE BETWEEN HEROES** — два связанных объекта создают пространство для заголовка между ними.
15. **ONE HERO + TWO SECONDARY OBJECTS** — один главный объект + два вторичных объекта, без перегрузки текстом.
16. **HERO + FLOATING INFO** — герой занимает основную массу, небольшие плашки находятся в свободных областях.
17. **EDITORIAL CENTER** — надзаголовок + умеренный чистый заголовок + герой + минимум вторичной информации.
18. **EDITORIAL ASYMMETRY** — смещённый герой + уравновешивающая типографика + одна небольшая плашка.
19. **DIAGONAL HERO + TYPE** — герой и текст работают по диагональной оси, плашка вторична.
20. **DIAGONAL TYPE + HERO** — диагональ формируется типографикой, объект стабилизирует композицию.
21. **FRAME OF INFORMATION** — герой внутри композиции, несколько компактных плашек формируют визуальную рамку.
22. **TEXT UNDER HERO** — герой получает основной визуальный вес, чистый заголовок располагается ниже/рядом.
23. **TEXT OVER HERO** — заголовок частично располагается поверх героя, но сохраняет читаемость.
24. **HERO BEHIND TYPE** — объект находится на втором плане, типографика впереди.
25. **HERO IN FRONT OF TYPE** — объект перекрывает часть заголовка и создаёт глубину.
26. **TITLE + HERO + CITY PILL** — чистый коммерческий вариант с одной плашкой города, если город дан пользователем.
27. **TITLE + HERO + BENEFIT PILLS** — заголовок + герой + 1–3 плашки преимуществ, только если преимущества даны пользователем.
28. **BRAND / OVERLINE + TITLE + HERO + INFO GROUP** — небольшой верхний уровень + заголовок + герой + компактная группа информации.
29. **PRODUCT PAIR + TITLE + INFO** — пара товаров как главный герой + заголовок + небольшая информационная группа.
30. **FREE COMPOSITION** — нестандартная архитектура, собранная из параметров системы; использовать, если предыдущие схемы становятся похожими.

# REFERENCE DNA — ЧТО НУЖНО БРАТЬ ИЗ РЕФЕРЕНСОВ

Референсы пользователя показывают не обязательную формулу «огромный заголовок + огромный объект».

При анализе нужно искать:

- умеренно крупный или крупный, но чистый заголовок;
- небольшой надзаголовок, если он есть;
- аккуратные информационные плашки;
- 1–3 вторичных информационных элемента;
- один главный объект или понятную группу объектов;
- тематический фон;
- грамотный баланс между героем, текстом и воздухом;
- чёткую информационную иерархию;
- профессиональную плотность без перегруза.

**Главный заголовок не обязан быть гигантским.**

Сильная обложка может быть построена на:

> чистом заголовке + главном объекте + 1–3 аккуратных плашках + тематическом фоне.

Не увеличивать текст искусственно ради эффекта.

---

# ANTI-REPETITION ENGINE — ОБЯЗАТЕЛЬНО

Главная задача — не допускать одинаковых обложек.

При каждой новой работе менять не только цвет, фон и фотографию, но и **архитектуру**.

Минимум **4 из 6 параметров** должны отличаться от предыдущей работы:

1. положение главного героя;
2. положение главного заголовка;
3. типографическая иерархия;
4. количество и расположение плашек;
5. роль героя относительно текста;
6. общая геометрия композиции.

Зеркальное отражение существующей композиции не считается новой схемой.

### Нельзя подряд повторять

- одинаковое количество плашек;
- одинаковую структуру надзаголовка и заголовка;
- одинаковое положение героя;
- одинаковую роль героя;
- одинаковое взаимодействие героя и текста;
- одинаковую плотность;
- одинаковую вертикальную позицию заголовка;
- одинаковый композиционный силуэт.

### Чередовать

- центральные композиции;
- боковые;
- диагональные;
- асимметричные;
- объектно-доминирующие;
- типографически доминирующие;
- editorial/minimal;
- композиции с 0 плашек;
- композиции с 1 плашкой;
- композиции с 2–3 плашками.

### Финальный тест

Перед созданием задать вопрос:

> **Если убрать цвет, фотографию и декоративные детали, будет ли архитектура этой обложки заметно отличаться от предыдущей?**

Если нет — пересобрать композицию.

---

# ЧТО НЕЛЬЗЯ ДЕЛАТЬ

Не превращать обложку в:

- универсальный AI-рекламный баннер;
- UI-интерфейс из карточек;
- перегруженный маркетплейс;
- шаблон «текст слева + человек справа»;
- набор случайных иконок;
- набор случайных badges;
- чрезмерно крупную типографику без причины;
- множество мелкого текста;
- декоративный мусор.

Каждый элемент должен иметь понятную композиционную функцию.

# FINAL QUALITY CONTROL

## FORMAT

- 1920×768 px.
- Финальный размер.
- Без обязательного 2×.

## SAFE ZONE

- важный контент только Y=130–718;
- верхние 130 px свободны от важной информации;
- нижние 50 px свободны от важной информации;
- фон может занимать весь canvas.

## ARCHITECTURE

- есть один понятный главный герой или главная визуальная масса;
- есть ясный главный заголовок;
- надзаголовок используется только при необходимости;
- количество плашек осознанно выбрано;
- плашки не выглядят как UI-карточки;
- информационная иерархия читается быстро;
- композиционный силуэт отличается от предыдущей работы.

## TYPOGRAPHY

- заголовок читается в уменьшенном размере;
- шрифт соответствует нише и референсу;
- нет tattoo-эстетики без прямой команды;
- нет случайных декоративных шрифтов;
- нет выдуманного текста.

## IMAGE

- главный объект соответствует нише;
- масштаб объекта осознанный;
- объект естественно интегрирован;
- свет и перспектива согласованы;
- нет случайных AI/stock-композиций.

## CONTENT

- используются только данные пользователя;
- нет придуманных преимуществ;
- нет придуманных услуг;
- нет придуманных фактов;
- нет лишних CTA;
- нет лишних иконок;
- нет случайных badges.

## ФИНАЛЬНЫЙ ВОПРОС

> **Похожа ли эта работа на новую работу из существующего портфолио пользователя, но не на копию предыдущей?**

Если нет — пересобрать композицию до создания изображения.
